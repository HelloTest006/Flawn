# Flawn SIMD, Memory Model & Hardware Auto-Tuner

## 1. Why Flawn Beats Standard C/C++ on Numerical Kernels

In standard C and C++, pointers can alias (`float* a` and `float* b` might overlap in memory), and floating-point addition is strictly non-associative. Even at `-O3`, standard C++ compilers often emit a single vector accumulator loop whose throughput is bottlenecked by the 4-cycle read-after-write latency of the CPU's FMA execution port.

Flawn eliminates both bottlenecks by design:
1. **Zero-Alias Arena Slices (`FLAWN_RESTRICT`)**: Every `f32[]`, `f64[]`, and `i64[]` slice allocated from Flawn's `SlabArena` is 64-byte cache-line aligned and guaranteed non-aliasing.
2. **Multi-Accumulator AVX2 FMA3 Unrolling**: `@simd` loops use 8 independent 256-bit YMM accumulators (`acc0`..`acc7`), processing **64 floats per loop iteration** via `_mm256_fmadd_ps` with hardware prefetching (`_mm_prefetch`), saturating all FMA ports.
3. **Persistent Spin-Barrier Thread Pool (`@parallel`)**: Instead of spawning OS threads per loop (`std::thread` creation costs ~50–100 µs), Flawn maintains a persistent spin-barrier worker pool (`_mm_pause` + atomic epoch release/acquire) with sub-microsecond dispatch latency.

## 2. Optimization Decorators

Decorate any function or loop with Flawn's hardware annotations:
- `@simd`: Forces SIMD vectorization (`#pragma GCC ivdep` + AVX2 FMA3 intrinsic lowering).
- `@parallel` (or `@par`): Partitions the loop across all CPU cores using Flawn's persistent spin-barrier worker pool.
- `@fastmath`: Enables associative floating-point algebraic reductions and reciprocal approximations.
- `@autotune`: Binds kernel tiling and unroll factors to the constants generated by `flawn tune`.

---

## 3. Hardware Auto-Tuner (`flawn tune`)

Running `flawn tune` executes an empirical benchmark sweep directly on your machine:
1. Queries CPUID for processor brand, core count, and ISA support (`AVX2`, `FMA3`, `AVX-512`).
2. Allocates 64-byte aligned arena buffers and times multiple micro-kernels across unroll factors (`2x`, `4x`, `8x`) and hardware prefetch distances (`128B`, `256B`, `512B`).
3. Writes the winning parameters to `include/flawn_tune_profile.hpp`, which are automatically compiled into subsequent `flawn build` and `flawn run --aot` invocations.
